# Windows_SC

Windows 11のスタートメニューと一緒に表示できる、常駐型の個人向けランチャーです。
アプリ、ファイル、フォルダー、URL、コマンド、音声出力先、マスター音量を
一つの画面から操作できます。

現在の公開版は`0.6.2-beta.1`です。GitHub Releaseで公開している知人向けの
最初のβ版であり、正式版ではありません。

## 対応環境

- Windows 11 25H2以降（OSビルド26200以降）
- x64
- 下端タスクバー
- 1080p以上でランチャーを配置できる作業領域

Windows 10、Windows 11 24H2以前、x86／ARM64、下端以外のタスクバーは
現在のサポート対象外です。起動時に対応環境を検査し、対象外の場合は理由を
表示して終了します。

## 基本操作

アプリを起動すると通知領域へ常駐します。ランチャーは次の方法で表示できます。

- Windowsキー単体
- タスクバーのスタートボタン
- `Ctrl+Alt+Space`
- 通知領域アイコンの「ランチャーを表示」

通知領域アイコンから、ランチャー表示、設定、アプリ終了を選択できます。

## 登録できる項目

- ボタン
  - アプリ、ファイル、フォルダー、URLを開く
  - コマンド／batを実行する
- 循環切り替え
  - 音声出力デバイスを登録順に切り替える
  - 複数のコマンドを登録順に実行する
- 音量スライダー
  - 現在の既定音声出力のマスター音量を変更する

起動対象欄のフォルダーアイコンから、ファイルまたはフォルダーを選択できます。
PATHで解決できる`notepad.exe`等、URL、Windows URIは手入力も可能です。

## 設定

設定は自動保存されません。設定画面下部の「保存」を押した時点で、入力検証、
設定ファイル保存、自動起動の反映、ランチャー表示の更新を行います。

主な設定:

- スマートフォン連携パネル用の表示位置調整
- 標準／コンパクト表示
- Windowsログオン時の自動起動
- ランチャー項目の追加、編集、削除、並べ替え
- 通常ログと詳細診断

## データ保存場所

設定とログは次へ保存します。

```text
%LOCALAPPDATA%\Windows_SC\
├─ Settings\
└─ Logs\
```

設定画面の「データフォルダーを開く」から確認できます。アプリが設定やログを
外部へ自動送信することはありません。詳細ログにはコマンドや音声デバイス名等が
含まれる可能性があるため、共有前に内容を確認してください。

## 開発用ビルド

```powershell
dotnet build Windows_SC.slnx -c Debug -p:Platform=x64
dotnet build Windows_SC.slnx -c Release -p:Platform=x64
```

配布物はx64自己完結版です。利用先にVisual Studio、.NET SDK、Windows App SDKを
別途インストールする必要はありません。

配布物は次の2種類です。

- `Windows_SC-0.6.2-beta.1-x64.zip`: 通常ZIP版。展開後、フォルダー内の
  `Windows_SC.exe`を実行する。起動が安定し、問題発生時に中身を確認しやすいため
  基準となる配布形式。
- `Windows_SC-0.6.2-beta.1-x64-single.exe`: 単一EXE版。ファイルは1個だが、
  初回起動時に内部ファイルを一時領域へ展開するため、通常ZIP版より起動に時間が
  かかる場合がある。

両方ともアプリ本体の機能は同じです。自動起動を有効にした後でファイルや
フォルダーを移動すると登録先が古くなるため、移動後は設定から自動起動を
設定し直してください。

現在、タスクバー中央揃えでスマートフォン連携パネルを表示した場合と、
一部の720p環境で、スタートメニューとランチャーの間隔が広くなることを
確認しています。パネルの正確な外周を安定して取得できないため、正式版までの
既知の配置課題として管理しています。

配布物の作成:

```powershell
.\scripts\Build-Distribution.ps1
```

成果物は`artifacts\distribution`に作成されます。詳しくは
[配布手順](docs/DISTRIBUTION.md)を参照してください。
