# UI・MVVM整理の残作業計画

更新日: 2026-11-06。この計画は実装・確認が完了するまで現行docsで管理する。
完了済みPhaseの詳細・古いテスト件数は[進捗履歴](archive/UI_MVVM_PLAN_PROGRESS_2026-11-06.md)へ退避した。
現行仕様は[設計](DESIGN.md)と[機能保守](FEATURE_MAINTENANCE.md)に分離する。

## 現在地

製品はWindows_SCとWindows_SC.Coreの2プロジェクト。Coreに設定検証・移行、保存調整、
入力列、マクロ、音声ID解決、履歴・表示更新調整を置き、Windows_SC.TestsがCore成果物を参照する。
DiagnosticsSettingsViewModel／DiagnosticsPanelは分離済み。SettingsSaveValidatorはGUI本体側にある。
設定保存競合、音量連続入力、キー記録の解除、非同期終了・通知は修正済みだがGUI確認は未完了。

## 残す実装単位

| 対象 | 残作業と完了条件 |
|---|---|
| 設定UI（旧Phase 5） | 種類別Editorと音声・アプリ候補の責務を整理する。保存前検証・失敗項目再選択・ロールバック・未保存保護を維持してGUI確認する |
| ランチャー（旧Phase 6） | 音量表示状態と標準／コンパクトXAMLの重複を検討する。履歴は既にSystemMetricsState側へ移動済み。サイズ・折返し・反転・非表示更新抑止を確認する |
| 構成・所有権（旧Phase 9） | Appを構成ルートとして生成・イベント接続・終了順を明示する。不要なクラス分割はせず、必要な整理だけを行う |
| 入力境界 | 可変DTO・編集途中の値・検証済みの内部値を区別する。型と所有権を確定してから互換変換・正規化・欠落補完の重複を減らす |
| 検証・配布 | 保存中終了、音量連続入力、記録中の項目切替、入力失敗、GUI Bindingを確認する。配布時は新規ZIP・別フォルダー・別PCを確認する |

## 実装方針

- 外部入力はJSON読込・設定保存等の入口で検証し、内部は型が確定した値を受け取る設計を目指す。
  現在の可変DTOに対する必要な防御を、型を変える前に一括削除しない。
- 再利用しない小処理は呼び出し箇所へ書く。複雑な処理や寿命・失敗時の責任を分ける関数は維持する。
- Start検出、Composition、音声COMを同時に大きく再設計しない。
- 明示保存と診断設定の直列化、旧設定保護、両スタート起動経路を維持する。
- 関連Coreテスト、変更に応じたビルド、[手動チェック](TEST_CHECKLIST.md)を実施する。
  全確認が終わったら計画を日付付きでarchiveへ移す。
