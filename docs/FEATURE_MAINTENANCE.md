# 機能保守ガイド

更新日: 2026-09-05
対象: ShortcutKey、マクロ、音声循環、アプリ別音量、システムモニター

## 1. 文書の位置付け

本書は、ランチャー項目として追加された操作・音声・Widget機能の現行仕様と変更時の
不変条件をまとめる。利用者向け概要は[README](../README.md)、全体構造は
[設計書](DESIGN.md)、設定モデルとCore境界は`Windows_SC.Core`、GUI・実機確認は
[簡易テストチェックリスト](TEST_CHECKLIST.md)を正とする。

## 2. アクションとマクロ

### 操作種類と互換性

- 設定画面は「アプリ・ファイル・URL」「コマンド・bat」「キー入力」「マクロ」の4分類で表示する。
- 設定JSONでは`Application`、`File`、`Url`、`Command`、`BatchFile`、`ShortcutKey`、`Macro`を
  別の列挙値として維持する。`Application`、`File`、`Url`を`Command`へ統合しない。
- マクロの操作ステップは既存のApplication／File／URL／Command／BatchFile／ShortcutKeyを再利用する。
  マクロの入れ子、分岐、ループ、マウス記録は扱わない。

### ShortcutKey

- グローバルホットキーではなく、登録したランチャーボタンを押したときだけ`SendInput`で送信する。
- F1や英数字等の単体キーを許可し、修飾キーだけ、`Ctrl+Alt+Delete`、固定ホットキー
  `Ctrl+Alt+Space`は拒否する。
- 送信前にランチャーの退出完了とフォーカス復帰を待つ。この経路はマクロ内ShortcutKeyにも適用する。
- 送信先は送信時点の前面ウィンドウとし、操作開始時のウィンドウへ固定しない。フォーカス変化に関係なくWindows全体へ認識される入力として送る。
- 送信前に物理修飾キーの状態を補正せず、現在の`SendInput`配列をそのまま送る。この挙動は現行仕様として維持する。
- 修飾キー押下、本体キー押下・解放、修飾キー逆順解放を1回の`SendInput`で送る。
- 項目ごとに`ScanCode`または`VirtualKey`を保存する。既定は`ScanCode`とし、
  ScanCode方式の矢印、Windowsキー等には拡張キーフラグを付ける。
- キー記録中は物理入力とWindowsキー監視、`Ctrl+Alt+Space`を抑止し、Escでキャンセルする。
  項目変更、削除、種類変更、設定画面破棄でも抑止を必ず解除する。

### マクロ実行

- `Action`または`Wait`を登録順に実行する。最大50ステップ、1待機0～10000ms、合計60秒を上限とする。
- アプリ全体で同時に1マクロだけ実行し、再押下は拒否する。
- ステップ失敗時は後続を実行せず、番号と表示名を利用者へ示す。終了時は実行をキャンセルする。
- 通常ログには項目ID、ステップ番号、種類だけを残し、対象、コマンド、キー内容を出さない。

## 3. 音声出力とアプリ別音量

### 音声循環

- 登録順の2台以上をデバイスIDで管理する。表示名は現在の出力ではなく次の利用可能な出力先を示す。
- 切断中の候補は飛ばし、末尾から先頭へ折り返す。表示名や現在位置を永続キーにしない。
- デバイスIDはMMDevice形式を正規化し、大小文字差を区別せず比較する。

### サービス境界

- `WindowsAudioOutputService`は既定出力切替とマスター音量を担当する。
- マスター音量の取得結果には音量値とミュート状態を含め、エンドポイント通知でリアルタイム更新する。
  ミュート中はランチャーへ「ミュート」と表示する。
- `WindowsApplicationVolumeService`は既定Render／Multimedia上の音声セッションを担当する。
- Core Audioの列挙、通知、操作、解除、COM解放はMTA専用スレッドで直列化する。
- UIやCoreへPID、セッション識別子、COMオブジェクトを渡さない。

### 識別と状態保存

- 通常Win32アプリは正規化した実行ファイルパスで識別し、同一アプリの複数セッションを集約する。
  PID、表示名、Session Instance IDは永続キーにしない。
- 状態は`%LOCALAPPDATA%\Windows_SC\Settings\application-volume-state.json`へ保存する。
- 複合キーは`音声デバイスID＋識別子種類＋アプリ識別子`である。
- Windows_SCで操作した組み合わせだけを作成する。未保存の出力へ切り替えただけでは状態を作らない。
- 保存は400msのdebounce後に一時ファイルから置換し、不正ファイルは`corrupt`名へ隔離する。

### 通知と解放

1. Session Notification登録後に既存セッションを列挙する。
2. コールバックはMTA処理キューへ渡す。
3. 出力変更時はSession Events、Session Notificationの順に解除する。
4. Session、Manager、Endpointの参照を解放してから新しい出力へバインドする。
5. 終了時はアプリ別音量サービスを停止・解放してから音声出力サービスを破棄する。

マスター音量のエンドポイント通知は既定出力ごとに登録し、出力変更時と終了時に必ず解除する。

`MMDeviceEnumerator`等の共有RCWを`FinalReleaseComObject`で強制解放しない。解除失敗があっても
残りの解放と`CoUninitialize`を継続する。外部ミキサー変更は保存済みの組み合わせだけへ反映する。

## 4. システムモニター

- `LauncherItemKind.Widget`の現行種類は`WidgetKind.SystemMonitor`だけである。
- CPU、GPU、メモリから1つまたは2つを選ぶ。既定はCPU＋メモリとする。
- 2項目は使用率2行、1項目は現在値と最大60点・60秒のグラフを表示する。
- 標準／コンパクトとも2列幅で、高さは標準160 DIP、コンパクト80 DIPとする。
- CPUは`GetSystemTimes`差分、メモリは`GlobalMemoryStatusEx`、GPUはGPU EngineのPDH値から取得する。
- 値が取得不能または初回未確定の場合は`—`とし、0%と誤表示しない。
- システムモニター項目が存在する間は1秒間隔で更新し、非表示中も最大60点の履歴を保持する。
  60点未満の履歴は1秒刻みのまま右寄せし、表示幅全体へ引き伸ばさない。
- PDH Query、タイマー、イベントは終了時に解放し、毎秒の取得失敗を通常ログへ出さない。
- PDHの初期化・計測・解放は共通ゲートで直列化する。解放はバックグラウンドで行い、
  終了側は最大1秒待つ。計測が戻らない場合に同じハンドルを並行して閉じない。

## 5. 変更時の確認

- ShortcutKey: 複数修飾キー、Windows／矢印、単体キー、方式別保存、20回連続、直前アプリへの入力
- マクロ: 登録順、待機、途中失敗、再押下、キャンセル、マクロ内ShortcutKey
- 音声循環: 登録順、次候補表示、切断候補、折返し、2台以上の検証
- アプリ別音量: 2出力の異なる値、未保存出力、複数セッション、外部ミキサー、再起動、切断、終了
- システムモニター: 標準／コンパクト、1／2項目、GPU取得不能、非表示中の履歴保持、1～2時間常駐
- 通常ログへコマンド、キー内容、アプリ名、パス、デバイス名、セッション名を出さない。

Coreで自動確認する範囲は[Core自動テスト方針](CORE_TESTING.md)、GUIとWindows実機の手順は
[簡易テストチェックリスト](TEST_CHECKLIST.md)および
[Phase 5～6 詳細テスト手順書](PHASE5_6_TEST_PROCEDURE.md)を参照する。
