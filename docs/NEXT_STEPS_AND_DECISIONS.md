# 次に行う作業と判断が必要な内容

更新日: 2026-08-09
対象ソースバージョン: `0.8.1`

## 1. この文書の目的

現在のコード、確認済み範囲、配布状態を分け、次に実施する作業と判断事項を管理する。
日常の確認方法は[簡易テストチェックリスト](TEST_CHECKLIST.md)、正式公開前の
網羅試験は[Phase 5～6 詳細テスト手順書](PHASE5_6_TEST_PROCEDURE.md)を正とする。
`docs/archive`は過去の検討・試験記録であり、現行仕様の根拠には使用しない。

## 2. 現在地点

### 2.1 コードと版

- 現在のソースバージョンは`0.8.1`、MSIX用ビルドメタデータは`0.8.1.0`である。
- `Version.props`、`Package.appxmanifest`、`CHANGELOG.md`は`0.8.1`へ同期済みである。
- Debug／Release x64は警告0・エラー0、自動テスト30件は成功している。生成DLLの
  FileVersion `0.8.1.0`、ProductVersion `0.8.1`を確認済みである。
- `0.8.1`の版更新コミットは`main`へ反映済みである。公開済みの最新タグ／配布版は
  `v0.6.2-beta.1`で、`0.8.1`のタグとReleaseはまだ作成していない。

### 2.2 `0.8.0`で入っている主な変更

- 音声出力循環は、現在の既定出力ではなく次に切り替わる利用可能な出力先を表示する。
- コマンド循環も次に実行する操作を表示し、操作後に次の候補へ更新する。
- UI Automationのフォーカス通知が長時間稼働後に途絶えても、可視のスタート系
  ウィンドウを250ms間隔で確認するアイドルフォールバックを維持する。
- スタート検出ログへ検出元、要求から検出までの時間、UI Automationスキャン時間を追加した。
- 詳細ログは24時間モードに加え、手動で無効にするまで再起動後も続く常時有効モードを持つ。
- 接続中のディスプレイに1080p未満の解像度がある場合は未検証警告を表示し、
  利用者の確認後に起動を続ける。
- ShortcutKey送信と、操作・キー入力・待機を登録順に実行するマクロを追加した。
- 既定出力ごとに値を保存・復元するアプリ別音量スライダーを追加した。
- CPU、GPU、メモリを表示するシステムモニターを追加した。

### 2.3 現在確認できている実動作

`0.7.2`までの通常ログでは、Windowsキー経路、フォーカス通知、アイドルフォールバック、
設定保存、音声循環、音量変更、詳細ログ常時有効状態の再起動後維持を確認できている。
`0.8.1`ではDebug／Releaseビルドと単体テスト30件を確認済みであり、ShortcutKey、
マクロ、アプリ別音量、システムモニターを含むGUI確認は未実施である。簡易テストB、
1080p未満の警告表示、配布物、別PC確認もまだ代替できていない。

### 2.4 配布状態

- 現行の`Build-Distribution.ps1`はx64自己完結の通常ZIPだけを生成する。
- ローカルに残る配布物とGitタグは`0.6.2-beta.1`だけである。
- MSIXは公開配布しない。プロジェクト設定とマニフェストは開発互換性のため残す。
- 公開配布はZIPまたは単一EXEを目的とするが、単一EXEは過去に一部PCで
  WinUI初期化時のCOM例外`0x80040111`が発生したため、現在は生成しない。

## 3. 確認結果と現在の既知事項

### 3.1 自動起動の確認結果

2026-08-07の開発PCでは、実ユーザー`anxil`の
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`に`Windows_SC`が存在し、
現在動作中のDebug x64版EXEと登録コマンドが一致している。OSは00:37:43、Explorerは
00:37:51、Windows_SCはExplorerを親として00:38:51に起動し、通常ログにも00:38:52の
`[Startup] action=enable result=success`と`[Application] action=start result=success`が
残っている。この再起動では自動起動が正常に動作したと判断する。

以前の「Run値が存在しない」という結果は、Codexの隔離ユーザーの`HKCU`を確認した
ことによる誤判定だった。今後Codexからレジストリを確認する場合は、実ユーザーの
プロファイルSIDを特定し、`HKEY_USERS`以下の対象ハイブを明示して照合する。

### 3.2 配置上の制約

タスクバー中央揃えかつスマートフォン連携パネル表示時は、スタートとランチャーの
間隔が広くなる場合がある。1080p未満でも配置問題が生じる可能性があるが、現在は
検証環境を用意できない。パネルの正確な外周を安定取得できないため、現行は設定に
よる予約幅を使用し、重いUI Automation走査や推測幅を再導入しない。

## 4. 次に行う作業

### 4.1 最優先

1. 音声循環の表示が「次: デバイス名」となり、切替後に次候補へ更新されることを目視確認する。
2. 簡易テストBの変更機能と配布前項目を実施する。
3. 1080p未満を用意できる環境で、起動警告、続行、ログを確認する。用意できない間は未検証として扱う。

### 4.2 `0.8.1`を配布する場合

1. 確認済みの簡易テストAに続け、簡易テストBの変更機能と配布前項目を実施する。
2. `Build-Distribution.ps1`で`Windows_SC-0.8.1-x64.zip`を生成する。
3. 別フォルダーへ展開し、版表示、初回起動、設定保存、終了、自動起動を確認する。
4. 可能ならVisual Studioと.NET SDKのない別PCで同じ確認を行う。
5. README、変更履歴、版、配布用README、成果物名、SHA-256が一致することを確認する。
6. `v0.8.1`タグとGitHub Releaseを作成し、公開アセットを再確認する。

### 4.3 単一EXEを再採用する場合

1. ZIP配布の確認とは別作業として、単一EXE用発行設定を実装する。
2. `App.OnLaunched`前に失敗した`0x80040111`の再現条件を切り分ける。
3. 問題が発生したPCとクリーン環境で起動、設定保存、自動起動を確認する。
4. ZIPと単一EXEのどちらを正式な成果物にするか、検証結果で決める。

### 4.4 機能拡張の確認

マクロ、ShortcutKey、アプリ別音量、システムモニターはコード実装済みである。
実装計画は[コード実装記録](archive/FEATURE_EXPANSION_IMPLEMENTATION_PLAN_2026-08-09.md)として
アーカイブ済みであり、現行仕様は各メンテナンス文書を参照する。残る手動確認は
`TEST_CHECKLIST.md`と`PHASE5_6_TEST_PROCEDURE.md`を正として、次を重点的に確認する。

- ShortcutKeyとマクロの設定、保存、実行、失敗時停止
- 2台の音声出力でのアプリ別音量30%／70%復元と外部ミキサー追従
- システムモニターの表示、非表示時停止、長時間常駐
- アプリ別音量を使用した通常終了時のCOM解放とworker timeout不発生

## 5. 判断事項

| ID | 判断する内容 | 現在の方針 |
|---|---|---|
| D-01 | 正式版前の変更範囲 | 重大な不具合修正、文書同期、挙動を変えない小規模整理に限定する。 |
| D-02 | `0.8.1`を配布するか | 簡易テストAと開発PCの自動起動は確認済み。新機能を含む簡易テストB、現在版ZIP、別PCの結果後に判断する。 |
| D-03 | 公開配布形式 | MSIXは対象外。現在はZIPだけ生成可能。単一EXEは起動障害解消後の候補とする。 |
| D-04 | 自動起動の保証範囲 | 開発中の非パッケージDebug版は実レジストリとログオン起動を確認済み。選択した配布物でも再確認する。 |
| D-05 | 対応Windows | Windows 11 25H2・ビルド26200以降、x64、下端タスクバーを維持する。 |
| D-06 | 起動処理の非同期化 | 再現可能な遅延がない限り`1.0.0`までは変更しない。 |
| D-07 | 非対応環境試験 | `1.0.0`前にVM等で理由付き終了とプロセス残留なしを確認する。 |
| D-08 | 実行中ログローテーション | 現行は次回起動時に2MB超をローテーションする。実害が出るまで維持する。 |
| D-09 | 自動更新 | 初回正式版には含めない。 |

## 6. `1.0.0`へ進む条件

- 利用不能、データ破損、終了不能、意図しない実行につながる既知不具合がない。
- 自動起動を含む選択した配布形式を手元と別PCで確認している。
- 非対応環境試験を完了するか、未確認範囲を利用者向け文書へ明示している。
- スマートフォン連携パネルと1080p未満の未検証範囲を利用者向け文書へ明示している。
- `1.0.0-rc.1`で簡易テストA／Bと必要なPhase 6項目を実施している。
- README、変更履歴、版、タグ、配布物、Releaseアセットが一致している。

## 7. 推奨する直近の順序

1. 音声循環の次候補表示と簡易テストBを確認する。
2. `0.8.1` ZIPを生成し、別フォルダーと別PCで確認する。
3. 1080p未満の警告は検証環境を用意できるまで未検証として明示する。
4. `0.8.1`を配布するか、さらに修正して次版へ進むか決める。
5. 単一EXEの再調査はZIP配布の安定確認と分けて行う。
