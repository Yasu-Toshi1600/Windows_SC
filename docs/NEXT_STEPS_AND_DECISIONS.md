## 3. 次に行う作業

### 3.1 β版での追加バグ確認

知人環境で再現した問題は、通常ログと必要な場合だけ24時間の詳細ログを使って
再現条件を絞る。現時点では次を優先する。

- 起動不能、操作不能、設定消失、意図しない実行、例外終了を最優先で修正する。
- 体感だけの遅延は、ログの区間時間と再現条件を取得してから修正する。
- スマートフォン連携パネルの配置は、外周を安定取得できる新しい根拠がない限り、
  重いUI Automation走査や推測幅を再導入しない。

### 3.2 限定的なリファクタリング

正式版直前の回帰を抑えるため、外部動作と設定形式を変えない整理だけを行う。
現在の大きなファイルは次のとおりで、分割候補ではあるが一度に全面改修しない。

- `SettingsViewModel.cs`: 約1460行。設定項目編集、保存、診断操作の責務分離候補。
- `MainWindow.xaml.cs`: 約850行。表示状態遷移と画面イベント補助の整理候補。
- `WindowsAudioOutputService.cs`: 約690行。列挙、既定変更、音量制御の内部分割候補。
- `UiAutomationStartMenuInspector.cs`: 約550行。正式版前は構造変更を避ける。

優先するのは、重複ヘルパーの統合、命名整理、純粋な検証処理の抽出、
ログ文言の統一である。スタート検出、Composition状態機械、COM音声制御を
同時に作り替えない。

### 3.3 正式版候補の最小回帰確認

全項目の総当たりは行わず、次だけを確認する。

- Windowsキー、スタートボタンクリック、`Ctrl+Alt+Space`、通知領域から表示できる。
- Windowsキー、スタート終了、画面外クリック、Escapeで閉じられる。
- 仮想デスクトップを切り替えた後も表示できる。
- 通常ボタン、コマンド、音声循環、コマンド循環、音量スライダーを各1回実行できる。
- 設定を保存し、再起動後も内容が残る。
- 通常ログへ新しい未処理例外が記録されていない。

スタート連打、複数モニター、詳細ログ等は、関連コードを変更していなければ
過去の確認結果を利用してよい。不具合が再発した場合だけ詳細試験へ戻る。

### 3.4 `1.0.0`へ進む前の確認

1. R-11の非対応環境で、理由付きダイアログ表示後にプロセスが終了することを確認する。
2. 単一EXE版をSmart App Controlに遮断されない別PCまたはGitHub経由で起動確認する。
3. βで見つかった重大な不具合が0件であることを確認する。
4. 限定的なリファクタリング後に簡易テストA／Bを実施する。
5. `1.0.0-rc.1`の通常ZIP版と単一EXE版を同じソースから生成する。
6. RCを手元と別PCで確認し、重大な問題がなければ`1.0.0`へ更新する。

β期間中に修正版を知人へ再配布する必要がある場合だけ、先に
`0.6.2-beta.2`を作成する。同じ`beta.1`の成果物を差し替えない。

## 4. 判断が必要な内容

| ID | 判断する内容 | 選択肢と影響 | 推奨 |
|---|---|---|---|
| D-01 | 正式版前の変更範囲 | 新機能を追加するか、バグ修正と内部整理に限定するか。 | 決定済み。主要機能を凍結し、バグ修正と挙動を変えない小規模リファクタリングだけを行う。 |
| D-02 | 次の版番号 | β修正版を出すか、正式候補へ進むか。 | 再配布が必要なら`0.6.2-beta.2`、正式候補は`1.0.0-rc.1`、合格後は`1.0.0`とする。 |
| D-03 | 初回配布方式 | 通常ZIP版、単一EXE版、MSIXのどれを配布するか。 | 決定済み。x64自己完結の通常ZIP版と単一EXE版を配布し、通常ZIP版を基準形式とする。MSIXは今回は配布しない。 |
| D-04 | 自動起動の保証範囲 | どの配布形式で自動起動を保証するか。 | 決定済み。非パッケージの通常ZIP版と単一EXE版を対象とし、移動後は再登録が必要と明記する。 |
| D-05 | 対応するWindows | 現行どおりWindows 11 25H2・ビルド26200以降に限定するか、24H2へ広げるか。対象を広げる場合はスタート検出と対応環境検査の再試験が必要になる。 | 初回配布は現行範囲を維持し、24H2対応は実機またはVMを用意できた後に判断する。 |
| D-06 | R-10 起動処理の非同期化 | 音声初期化等をバックグラウンド化するか、現状を維持するか。変更は起動順序と終了処理へ影響する。 | `1.0.0`までは現状維持。起動遅延が再現した場合は先に区間ログを追加し、原因を絞ってから変更する。 |
| D-07 | R-11 非対応環境試験 | 正式版前に実施するか、未確認リスクとして残すか。安全な24H2またはx86 VMが必要になる。 | `1.0.0`前に理由付き終了とプロセス残留なしを確認する。環境を用意できなければ未確認範囲をREADMEへ明示する。 |
| D-08 | R-12 実行中ログローテーション | 2MB超過時に即時ローテーションするか、現行の次回起動時処理を維持するか。 | `1.0.0`は現行仕様を明記して維持し、長時間試験で実害が出た場合に実装する。 |
| D-09 | 更新機能 | `1.0.0`へ自動更新または更新確認を追加するか。署名、配布元、失敗時復旧等の設計が必要になる。 | 初回正式版には含めず、配布手順が安定してから別フェーズで設計する。 |
| D-10 | 正式版の番号 | 身内向けの最初の安定版を何番にするか。 | 決定済み。βでバグ取りと限定的なリファクタリングを行い、`1.0.0-rc.1`を経て`1.0.0`とする。 |

## 5. 現時点で判断し直す必要がない内容

次の内容は仕様確定・実装・確認済みのため、関連する不具合が出ない限り
再設計しない。

- 標準表示とコンパクト表示の基本レイアウト
- 長い表示名の最大2行表示と種類ラベル
- 音量スライダーの配置とホイール変化量
- 項目一覧とトラブルシューティングのスクロール
- 明示的な保存方式
- コマンド循環の「失敗時は同じ操作を再実行する」の廃止
- UI Automation要素名をログへ記録しない方針
- 詳細ログ期限を診断設定の適用時だけ更新する方針
- 仮想デスクトップ移動時の表示処理

## 6. `1.0.0`の区切り

### 完了済み

- 主要機能、設定UI、ログ、トレイ、自動起動を実装済み。
- 通常ZIP版と単一EXE版を再現可能に生成済み。
- `0.6.2-beta.1`をGitHub Releaseへ公開済み。
- 主要な優先度A／B不具合とv0.6 UI項目を実画面確認済み。

### 正式版へ進める条件

- β版で利用不能、データ破損、終了不能、意図しない実行につながる既知不具合がない。
- `1.0.0-rc.1`を手元と別PCで簡易テストする。
- 選択した配布形式の自動起動を確認している。
- R-11の非対応環境試験を完了するか、正式版の対応環境表示と
  未確認リスクを明示している。
- スマートフォン連携パネルと720pの間隔問題を修正するか、既知の制約と
  設定上の回避方法を利用者向け文書へ明示している。
- README、変更履歴、バージョン、配布物の内容が一致している。

## 7. 推奨する直近の順序

現時点では、次の順序が最も小さい負担で`1.0.0`へ進められる。

1. β版利用中に見つかった再現可能な不具合を整理・修正する。
2. 大きなクラスを一つずつ、挙動を変えない範囲で整理する。
3. R-11、単一EXE別PC、スマートフォン連携／720pの扱いを確定する。
4. 簡易テストA／B後に`1.0.0-rc.1`を作成する。
5. RCで重大な問題がなければ`1.0.0`を作成・公開する。
