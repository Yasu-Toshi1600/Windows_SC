# 音声登録先の消失と削除時クラッシュの調査

更新日: 2026-09-08。GUI検証とクラッシュ原因の確定が未完了のため現行docsで管理する。

## 確認した事実

- NVIDIAドライバーを前日に更新したとの利用者報告あり。モニター音声は9月4日と9月8日の成功ログでIDが異なり、旧IDは現在のWindows出力一覧にない。更新との因果関係は有力だが直接の記録はない。
- 設定画面は取得一覧に登録IDがないと「不明なデバイス」を表示していた。IDのみの保存では旧表示名を復元できない。
- 9月8日13:37:53、0.9.5でアクセス違反（0xc0000005）。利用者によれば不明な音声行の×を押した際に発生。
- 保存済みダンプをWinDbgで解析。実際のDLL（checksum 00E63B9A）とPDBを照合済み。
- 呼び出し履歴はListViewBaseItem::OnPointerEntered → 表示状態変更 → CListViewBaseItemChrome::SetSelectionIndicatorBackground → CDependencyObject::SetValueByKnownIndex。
- 削除処理は対象を選択してから削除し、別行を選択する。連続した選択変更とマウス状態更新の関係が疑われるが、原因確定ではない。音声COM操作はこの削除経路では行わない。
- ミニダンプには対象UIのヒープがなく、どの内部オブジェクトが不正だったかは読み取れない。

## 実機での再現確認

- 既存0.9.5の設定画面で、不明なデバイス行の×をUI Automation Invokeで1回実行。行は消えたがプロセスは生存、新規クラッシュ記録なし。
- 物理クリックはクリック可能位置を取得できず未成立。同条件の再現成功・再現しないことの証明にはならない。
- 設定画面を閉じて未保存変更を破棄。保存JSONのSHA-256は前後で一致。
- ローカルのartifacts/crash-21732-detail2.logに詳細解析結果。ダンプ、設定控え、画面画像には個人情報が含まれ得るためコミット・配布対象にしない。

## 音声登録先の改善

- [x] StableId取得・保存と、現在のエンドポイントIDへの照合を実装。既存登録は接続中に保存して情報を保持する。
- [ ] StableIdの実機取得、ドライバー更新前後の追従、設定保存・再起動を確認。削除クラッシュの解消とは別扱い。

- [x] IDと別に表示名を保存し、未接続時の設定表示へ利用する。名前で自動同定しない。
- [x] 登録順を維持する明示的な差し替え操作。保存するまで実設定へ反映しない。
- [ ] GUIで旧設定読込、未接続表示、差し替え、保存・再起動を確認。
- [ ] ドライバー更新後の別IDへの復旧を実機確認。
- [ ] 削除クラッシュはフルダンプまたは物理クリックでの再現による追加調査が必要。今回修正済みとは扱わない。

保守仕様は[機能保守ガイド](FEATURE_MAINTENANCE.md)に分離する。調査完了時に本書を日付付きarchiveへ移す。
