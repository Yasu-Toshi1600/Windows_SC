# Windows_SC 簡易テストチェックリスト

更新日: 2026-09-06
対象: Windows_SC `0.8.0`以降を一人で開発・配布確認する場合の標準手順

## 1. 基本方針

終了処理を変更した場合は、トレイ／設定からの終了、保存中の終了、長時間稼働と
スリープ復帰後の終了を確認し、アイコンだけでなくプロセスが消えることを確認する。
WM_CLOSEによるプログラム試験は手動操作の代替としない。
今回の実施結果は[終了処理の調査記録](SHUTDOWN_INVESTIGATION_2026-09-06.md)を参照。

すべての環境と異常系を毎回試す必要はない。変更の大きさに応じて次の3段階を使う。

| 段階 | 実施時期 | 所要時間の目安 |
|---|---|---:|
| A: 日常確認 | 普段の修正後 | 5～10分 |
| B: 配布前確認 | 知人へ渡す前、バージョン更新時 | 30～45分 |
| C: 追加確認 | 関係する機能を大きく変更したとき、不具合を再現するときだけ | 必要な分だけ |

通常はAだけでよい。知人へ新しい配布物を渡す前にAとBを行う。詳細な全項目は[Phase 5～6 詳細テスト手順書](PHASE5_6_TEST_PROCEDURE.md)を参照するが、個人配布のたびに全項目を実施する必要はない。

## 2. 判定方法

- `PASS`: 期待どおり動作した。
- `FAIL`: 再現可能な不具合があった。
- `N/A`: その環境では試せない。例として、モニター1台の環境における複数モニターテストが該当する。

必須項目にFAILがなければ次へ進める。N/Aは不合格ではない。別PCで確認できたときに結果を補う。

不具合が出た場合だけ、次を残す。

```text
アプリバージョン:
操作:
期待した動作:
実際の動作:
再現回数:
発生時刻:
通常ログ:
詳細ログ: 必要な場合のみ
```

## 3. A: 日常確認

コードまたは設定画面を変更した後に行う。

### A-1 ビルドと起動

- [ ] `Windows_SC.Tests`のCore自動テストがすべて成功する。対象範囲は[Core自動テスト方針](CORE_TESTING.md)を参照する。
- [ ] x64 DebugまたはReleaseがエラーなしでビルドできる。
- [ ] 起動時にランチャーや設定画面が勝手に開かず、トレイアイコンが1個表示される。
- [ ] 終了後にプロセスとトレイアイコンが残らない。
- [ ] 1080p未満を用意できる場合、起動時に未検証警告が表示され、OK後は常駐を続ける。

### A-2 表示と終了

- [ ] Windowsキーで5回開閉できる。
- [ ] スタートボタンのクリックで5回開閉できる。
- [ ] `Ctrl+Alt+Space`で表示と非表示を切り替えられる。
- [ ] `Ctrl+Alt+Space`で表示後、ランチャーへ一度も触れず画面外をクリックして閉じる。
- [ ] 通常の画面外クリックとEscapeですぐ閉じる。
- [ ] 最大化した通常ウィンドウを前面に置いた状態でWindowsキーを押し、ランチャーがその背後に隠れず最前面へ表示される。もう一度Windowsキーを押す場合と、別ウィンドウをクリックする場合の両方で閉じる。
- [ ] 休止状態から復帰後、ログの`[Recovery] action=resume result=success`で`launcher`、`input`、`start-menu`がすべて`success`となる。その後に同じ表示・終了操作を行い、`verify-presentation result=success`が`visible=true topmost=true cloaked=false`となる。画面上の結果とログが一致する。
- [ ] スリープ／休止状態からの復帰後、通常ログと有効中の詳細ログがローテーションされ、復帰処理が新しい現行ログへ記録される。
- [ ] 仮想デスクトップ1→2→1を移動し、各デスクトップでWindowsキー、スタートボタン、`Ctrl+Alt+Space`、トレイから1回目の操作で表示できる。Windowsキー経路ではランチャーが直前のデスクトップへ残らず、ログに`0x8001010D`が出ない。

### A-3 基本操作

- [ ] 登録済みボタンを1個実行でき、成功後に閉じる。
- [ ] 設定画面を開き、項目を1つ変更して「保存」するとランチャーへ反映される。
- [ ] 保存せず設定画面を閉じた変更はランチャーへ反映されない。
- [ ] 保存処理中に設定画面を閉じて再表示しても保存が競合せず、保存処理中に終了した場合は保存完了後にプロセスが終了する。

A-1～A-3がすべてPASSなら、通常の修正確認は完了とする。

## 4. B: 配布前確認

Aを実施した後、知人へ新しい版を渡す前に行う。

### B-1 ランチャーの入口

- [ ] Windowsキーを10回連続で開閉して、起動漏れ、二重表示、遅い退出がない。
- [ ] スタートボタンを通常速度で10回開閉できる。
- [ ] スタートボタンを2～3回やや速く操作しても、その後操作不能にならない。
- [ ] トレイの「ランチャーを表示」「設定」「終了」が動く。

連打速度を競うテストは不要である。通常利用より少し速い操作で状態が取り残されないことだけ確認する。

### B-2 項目と設定

- [ ] アプリ／ファイル起動を1件実行できる。
- [ ] コマンドまたはbatを1件実行できる。
- [ ] 2件以上の循環切り替えが`1 → 2 → 1`の順で動く。
- [ ] 音声／コマンド循環の表示が現在値ではなく「次: 切替先」を示し、操作後に次候補へ更新される。
- [ ] コマンド循環を「表示したまま」・画面表示ありで実行し、コマンド画面へフォーカスが移ってもランチャーが閉じない。
- [ ] 音声デバイス循環を利用する環境では、切り替えと再接続後の復帰を確認する。
- [ ] 設定画面を開いたまま音声デバイスを接続・切断し、更新ボタンで候補と利用可否が更新される。
- [ ] 音量スライダーを安全な範囲で動かせる。
- [ ] ランチャー表示中に既定音声出力をミュートすると、マスター音量スライダーがリアルタイムで「ミュート」表示になり、解除すると現在の音量表示へ戻る。
- [ ] ShortcutKeyを記録・保存し、ScanCode／VirtualKeyの両方式で直前に操作していたアプリへ入力される。修飾キー複数と矢印キーを含む入力、20回実行でキーが押されたままにならない。
- [ ] ShortcutKeyの退出待機中に前面アプリを切り替えた場合、送信時点で前面のアプリへ入力される。物理修飾キーを押した状態でも現行の入力結果を確認する。
- [ ] F1や英数字などの単体キーを修飾キーなしで記録・保存・実行できる。
- [ ] Windowsキーを含む組み合わせを記録でき、記録中にスタートメニューや対象のWindowsショートカットが発動しない。Escでは保存せずキャンセルされる。
- [ ] ShortcutKeyの送信方式を保存して設定画面を開き直し、現在値が空欄にならず選択欄へ表示される。
- [ ] ボタンの実行種類が「アプリ・ファイル・URL」「コマンド・bat」「キー入力」「マクロ」の4分類で表示され、既存のFile／URL／BatchFile設定も対応する分類で開ける。
- [ ] マクロのステップを選び直したとき、ステップ種類と実行種類の現在値が空欄にならず、実行種類が3分類で表示される。
- [ ] マクロが登録順に動き、途中失敗で停止し、実行中の再押下を拒否する。
- [ ] アプリ別音量の候補更新、選択、保存、再起動後の編集ができる。
- [ ] 同じアプリを出力先Aで30%、Bで70%へ設定し、両方向の切替で対応値だけが復元される。
- [ ] アプリ別音量を表示・操作した後に通常終了し、`InvalidComObjectException`、`worker-timeout`が記録されない。
- [ ] 未保存の出力先へ切り替えた直後は、現在のアプリ音量が上書きされない。
- [ ] システムモニターでCPU、GPU、メモリから1つまたは2つを選択・保存でき、3つ目と0項目にはできない。
- [ ] 2項目では使用率だけが表示され、1項目では現在値と最大60秒のグラフが1秒ごとに更新される。非表示中も履歴を保持し、60点未満は右寄せで表示される。GPU取得不能時は`—`を表示する。
- [ ] 項目の追加、削除、上下移動後も対象を見失わない。
- [ ] ボタンには「実行後」が表示されず、循環切り替えには表示される。
- [ ] 再起動後も保存した内容、順序、レイアウトが維持される。

利用していない項目種類はN/Aでよい。ただし、新しく変更した種類は必ず確認する。

### B-3 レイアウトとモニター

- [ ] 標準／コンパクトを切り替えると列数が変わる。
- [ ] 長い表示名が最大2行で省略され、マウスを重ねると全文を確認できる。
- [ ] コンパクト表示でボタン、音声切り替え、音量スライダーの高さが揃い、後続項目がずれない。
- [ ] 標準／コンパクトのシステムモニターで、2項目の文字と1項目のグラフが見切れない。
- [ ] 音量スライダー上のホイールで2ずつ増減し、同時に一覧がスクロールしない。
- [ ] WQHD・125%でスタートメニューとランチャーの隙間が約5pxになる。
- [ ] 文字、ボタン、設定項目が見切れず操作できる。
- [ ] 複数モニター環境では、スタートとランチャーが同じモニターへ表示される。
- [ ] モニターが1台だけなら複数モニター項目はN/Aとする。

すべてのDPI、解像度、リフレッシュレートを一人で揃える必要はない。手元と知人PCで異なる構成が確認できれば、その結果を利用する。

### B-4 ログと配布物

- [ ] x64 Releaseをエラーなしでビルドできる。
- [ ] トラブルシューティングの環境情報にアプリ版、OSビルド、モニター情報が表示される。
- [ ] データフォルダーを開き、配下の`Logs`で通常ログを確認できる。
- [ ] 通常ログに起動時の環境情報があり、モニター構成等を変えた時だけ新しい環境情報が追記される。
- [ ] 詳細ログを有効化・無効化できる。
- [ ] 詳細ログ有効中に一般設定を保存しても、有効期限が延長されない。
- [ ] 詳細ログの常時有効を適用すると再起動後も継続し、手動で無効にすると追記を停止する。
- [ ] ログ削除のキャンセル／実行で確認ダイアログが競合せず、アプリが終了しない。
- [ ] 通常／詳細ログはそれぞれ現行を含む4ファイルだけ保持され、5世代目が残らない。
- [ ] 同じ`result=failed`を連続発生させた場合は集約行が記録され、ログ大量発生時もキューが5000件を超えて増え続けない。
- [ ] トラブルシューティング画面に共有前確認の注意があり、通常・詳細ログのどちらにもUI Automation要素名が記録されない。
- [ ] 設定変更時に未保存警告がオレンジで表示され、保存成功、入力警告、エラーが区別される。
- [ ] 設定一覧の選択背景が項目カードの境界と一致し、隣の項目へはみ出さない。
- [ ] 起動対象のフォルダーアイコンからファイルとフォルダーを選択でき、キャンセル時は入力内容が変わらない。
- [ ] 通常ZIP版のアプリ版が今回のバージョンと一致する。
- [ ] 通常ZIP版を別フォルダーへ展開し、`Windows_SC.exe`が起動する。
- [ ] Visual Studio、.NET SDK、Windows App SDKを別途要求しない。
- [ ] 可能ならVisual Studioと.NET SDKのない別PCで起動できる。
- [ ] 自動起動を有効にした直後、`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`の`Windows_SC`が現在のEXEを指し、次回ログオンで1プロセスだけ常駐する。
- [ ] 単一EXEを配布候補にする場合は、過去に`0x80040111`が発生したPCを含む対象環境で起動できる。

別PC確認を毎回依頼できない場合、コード変更だけの配布では前回のクリーン起動結果を流用してよい。ランタイム、配布方式、プロジェクト設定を変更した場合は再確認する。

## 5. 知人へ依頼する最小確認

知人には次の5項目だけ依頼すればよい。

1. 起動してトレイアイコンが出る。
2. Windowsキーとスタートボタンクリックで5回ずつ開閉できる。
3. スタートとランチャーが同じモニターへ表示される。
4. 標準／コンパクトで見た目が変わる。
5. 設定を1件保存し、再起動後も残る。

問題がなければログ提出は不要である。不具合が出た場合だけ、環境情報、発生時刻、通常ログを受け取り、必要な場合に限って詳細ログを有効にする。

## 6. C: 変更内容に応じた追加確認

次の項目は毎回実施しない。該当部分を変更した場合、または問題が疑われる場合だけ行う。

| 変更・状況 | 追加する確認 |
|---|---|
| スタート検出、Windowsキー、モーションを変更 | 途中反転20回、スタートクリック20回、Windowsキーショートカット、詳細ログ時間 |
| モニター配置、DPI、レイアウトを変更 | 異なるDPIの2画面、主画面変更、負座標、モニター再接続 |
| 正式版候補を作る | 1080p、WQHD 125%、タスクバー中央／左、スマートフォン連携パネルあり／なしの間隔。1080p未満を用意できれば起動警告も確認 |
| トレイ、常駐、終了を変更 | Explorer再起動、二重起動、終了後のプロセス残留 |
| 設定保存、保存場所を変更 | 不正JSON、配列ルート、スキーマ型違い、書込み失敗、旧データ移行、バックアップ復旧、将来版の警告終了、保存中終了 |
| 例外境界を変更 | 試験ビルドだけで未処理例外ログと終了動作 |
| 音声処理を変更 | 切断、再接続、既定デバイス変更、スリープ復帰 |
| アプリ別音量を変更 | 複数セッション、外部ミキサー、アプリ再起動、2出力の別値、未保存出力、状態保存失敗 |
| ShortcutKey／マクロを変更 | 直前のアプリへの入力、Windowsキーを含む入力、修飾キー複数、20回実行、途中失敗、キャンセル、再押下 |
| システムモニターを変更 | GPU取得不能、RDP、標準／コンパクト、非表示中停止、1～2時間のCPU・メモリ・ハンドル |
| ログ、匿名化を変更 | ユーザー名、実パス、UI Automation要素名が出ないこと、共有注意、ログ削除、5000件上限、連続失敗集約、4ファイル保持、復帰時ローテーション |
| 配布構成、.NET、Windows App SDKを変更 | クリーンPC、自己完結起動、自動起動、削除。単一EXEなら過去の障害PCも確認 |
| メモリ増加や停止が疑われる | 1～2時間の通常利用と、開始／終了時のメモリ・ハンドル比較 |

100回反転、8時間常駐、全DPI、全リフレッシュレート、RDP、スクリーンリーダーは、正式公開前または該当不具合の調査時だけ行う。知人向け初回配布の必須条件にはしない。

## 7. 配布可否

次を満たせば、知人向けの試験版を配布してよい。正式な安定版として公開する場合だけ、詳細テスト手順書のPhase 6条件も使用する。

- AがすべてPASS。
- Bで、変更した機能と基本起動にFAILがない。
- N/A項目の理由が分かっている。
- 既知の不具合が利用不能、データ破損、終了不能、意図しないコマンド実行につながらない。
- バージョンと配布物を区別できる。

細かな見た目、未所持の機器、特殊なDPI等の未確認は、試験版であることを伝えれば配布を止める理由にしない。

## 8. 簡易結果メモ

```text
日付:
バージョン:
コミット:
実施PC:

A: PASS / FAIL
B: PASS / FAIL / 一部N/A
C: 実施した項目だけ記載

不具合:
配布可否: 可 / 不可
```
